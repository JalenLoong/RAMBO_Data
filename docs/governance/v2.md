# v2 implementation of the documentation protocol

Read [the complete protocol](documentation.md) and [the shared registry](work-registry.json).
The protocol is recovered byte-for-byte; source.json fixes its original identity. Project-specific decisions live here, not in the generic document.

## Numbering and ownership
v1 and v2 are independent namespaces. Within v2, WAM and RAMBO share one registry; each category starts at 001. WAM owns reservations and RAMBO carries an identical declaration. Reserve before implementation, never reuse an ID, and carry the same ID through change, plan, commit/PR and attempt records. Use [CATEGORY-NNN] at the start of commit/PR titles. An existing combined infrastructure commit may name both registered works. A work need not have documents in a repository that does not participate.
ADR numbers are independent four-digit decision IDs with related_work links. Model versions, schemas and Python package names are not Work IDs.

## Lifecycle and routing
AGENTS and docs/INDEX route to authoritative pages. Current pages describe accepted semantics, research pages contain hypotheses, ChangeSpec defines intended observable changes, ExecPlan records execution, and ADR explains decisions. Complete/abandon paired work records together and move them out of active. Work index is generated from the registry. A completed engineering plan is not evidence of task success.
Create hypotheses/claim matrices only for actual research claims; do not fabricate them for this bookkeeping migration. PRs link the change, plan, decisions and actual attempts. Require source, synthetic, artifact and hardware evidence to be distinguished.

## Evidence and paths
Use configured workspace data/cache roots. Historical runs, absolute paths, source/model hashes and checkpoint identities stay immutable. [Migration aliases](migration.json) associate original evidence with current IDs; they do not claim those attempts ran at a new SHA. V2-PUBLISH is a historical publication grouping, not another business Work ID.
W&B remains the protocol's experiment system; future real experiments record Work ID, logical run, attempt, lineage and W&B identifiers. Local CPU migration checks retain local attempt records and explicitly state W&B not_run; do not invent historical runs or upload resources during governance work.

## Checks and publication
Run docs-check, import boundaries and affected CPU tests. Cross-repository governance check takes explicit --peer-root and compares the shared registry and original protocol hash without importing peer packages. Commit-title checking starts after repository.json's v2 history_base; v1/common history is excluded. Generic examples, fenced code and templates are not actual project paths.
DOC-001 explicitly authorizes local commits and exact-lease pushes to the configured v2 targets. This does not authorize later automatic publication, collection or training.
