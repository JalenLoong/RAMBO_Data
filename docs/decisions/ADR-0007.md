# User-approved Push Box success and diagnostic contact

The user approved on 2026-09-16: success is object in the target region and robot not fallen, optionally a short hold. Contact provenance is diagnostic only; imperfect pair evidence must not block collection. Unreliable contact must be explicitly unknown, never false. Existing bool columns alone cannot encode this validity; a later explicit task diagnostic representation will carry availability. No existing schema/profile bytes are changed by this decision.

This supersedes ADR-0006's requirement to resolve pair observability before task freeze/release, while retaining its source-timestamp inheritance, model input isolation and asset/coverage/geometry review boundary. The one strict new pre-pilot gate is terminal-before-reset: final-action boundary RGB/state must be captured and fixed before reset. This is an accepted user semantic decision, not runtime validation. Concrete assets/goal geometry are still pending review.
